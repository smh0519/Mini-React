# Mini React

이 프로젝트는 React의 동작 원리를 뼈대부터 이해하기 위해 핵심 기능을 직접 구현해보는 프론트엔드 프로젝트입니다. 복잡한 최신 기능들을 덜어내고, JavaScript가 어떻게 DOM을 관리하고 업데이트하는지에 대한 본질적인 원리를 단계별로 학습합니다.

## 학습 로드맵 및 진행 상황

### Step 1. 기초 공사: 그리기 (Rendering) 👈 [현재 위치]
**목표:** JSX(처럼 보이는 JS 객체)를 브라우저 화면에 띄우기

1. **`createElement` 구현:**
   - HTML 태그와 텍스트를 V-DOM(자바스크립트 객체)으로 변환합니다.
   - `children` 배열을 처리하여 텍스트와 일반 노드 객체를 구분합니다.
2. **`render` 함수 구현 (초기 버전):**
   - V-DOM 객체를 실제 DOM 노드로 변환합니다 (`document.createElement`).
   - 재귀적으로 자식 노드들을 생성해서 부모 요소에 붙입니다 (`appendChild`).

### Step 2. 구조 개선: 작업 단위 쪼개기 (Fiber Architecture)
**목표:** 렌더링을 멈추거나, 나중에 상태를 기억할 수 있는 트래킹 구조 만들기 (Hooks 구현을 위한 필수 단계)

1. **작업 루프(Work Loop) 만들기:**
   - `requestIdleCallback`을 사용해 브라우저가 한가할 때만 렌더링 작업을 수행하도록 합니다.
2. **Fiber 객체 설계:**
   - 단순한 V-DOM 객체에 `parent`, `child`, `sibling` 링크를 추가하여 트리 구조로 연결합니다.
3. **Render와 Commit 분리:**
   - 메모리 상에서 트리를 모두 구성한 뒤(Render Phase), 완성된 트리를 한 번에 실제 DOM에 적용(Commit Phase)하는 구조로 변경합니다.

### Step 3. 변화 감지: 비교와 갱신 (Reconciliation)
**목표:** 트리에서 바뀐 부분만 찾아서 효율적으로 DOM 업데이트하기

1. **Diffing 알고리즘:**
   - 새로운 Fiber 트리와 이전(Old) Fiber 트리를 비교합니다.
   - **태그가 바뀌었으면?** → 노드 생성 (PLACEMENT)
   - **태그는 같은데 내용만 바뀌었으면?** → 속성 업데이트 (UPDATE)
   - **노드가 없어졌으면?** → 노드 삭제 (DELETION)
2. **DOM 업데이트 로직:**
   - 변경된 속성(Props, Event Listener 등)만 실제 DOM에 반영합니다.

### Step 4. 컴포넌트와 상태: 함수형 컴포넌트 & useState
**목표:** `<App />` 같은 함수형 컴포넌트를 지원하고, 상태(State) 기억하기

1. **함수형 컴포넌트 처리:**
   - `type`이 문자열("div" 등)이 아니라 함수(Function) 형태일 때 내부 실행 로직을 분기하여 처리합니다.
2. **`useState` 구현:**
   - 컴포넌트 별로 `hooks` 배열을 만들어 내부 상태를 저장합니다.
   - `setState`가 호출되면 렌더링을 다시 트리거하여 화면을 갱신합니다.

### Step 5. 생명 주기와 부수 효과: useEffect
**목표:** 렌더링 후 외부 데이터를 가져오거나 DOM을 직접 조작하기

1. **`useEffect` 구현:**
   - 렌더링이 완전히 끝난 직후(Commit 단계)에 실행할 부수 효과(Side Effect) 작업을 예약합니다.
2. **의존성 배열(Dependency Array) 체크:**
   - `[count]`처럼 배열 내의 값이 이전 렌더링 시점과 다를 때만 콜백 함수를 실행합니다.
   - `[]` 빈 배열이 전달될 경우 컴포넌트가 처음 화면에 나타날 때(Mount) 한 번만 실행되도록 처리합니다.
